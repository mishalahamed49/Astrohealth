# AstroHealth

A .NET 8 Blazor WebAssembly health-monitoring interface with an ASP.NET Core API and MongoDB storage.

## Requirements

- .NET 8 SDK or a newer SDK with the .NET 8 targeting pack
- A MongoDB Atlas cluster with a database user and your development IP address allowed in Network Access

## Run locally

Set the Atlas connection string in .NET User Secrets (do not put credentials in `appsettings.json`):

```powershell
dotnet user-secrets init --project AstroHealth.Server
dotnet user-secrets set "MongoDB:ConnectionString" "mongodb+srv://<db-user>:<password>@<cluster-host>/" --project AstroHealth.Server
```

The app uses the `AstroHealthDb` database. `AstroHealth.Server/appsettings.json` contains the non-secret database name; User Secrets override the empty connection-string setting.

Start the API in one terminal:

```powershell
dotnet run --project AstroHealth.Server --launch-profile https
```

Start the Blazor client in a second terminal:

```powershell
dotnet run --project AstroHealth.Client --launch-profile https
```

Open the client at `https://localhost:7060`. The API Swagger UI is available at `https://localhost:7189/swagger`.

Use **Crew profiles** in the app to create and select individual reports. Dashboard readings, trends, body-system signals, and new check-ins are scoped to the active crew member. The `DemoAstronautId` value in `AstroHealth.Client/wwwroot/appsettings.json` determines which existing profile is selected by default at startup. If the client/API origins or ports change, update `Cors:AllowedOrigins` in the server's `appsettings.json`.

This local prototype does not require sign-in; profiles are for separating demo records, not access control.

The Development launch profile seeds 30 synthetic readings for `demo-astronaut-001` on first start, if that astronaut has no existing readings. Disable it with `SeedData:Enabled` in `AstroHealth.Server/appsettings.Development.json`. These are local demo values, not records generated by Synthea or NASA; the app marks them as synthetic.

## Build

```powershell
dotnet build AstroHealth.sln
```

The health thresholds and on-screen guidance in this prototype are illustrative; they are not medical advice and need qualified aerospace-medicine validation before operational use.
